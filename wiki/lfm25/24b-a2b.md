# LFM2.5-24B-A2B Architecture & Execution Specification

This document provides the complete architectural breakdown, mathematical execution pipeline, tensor inventory, and hybrid VRAM/Host caching strategy for **LFM2.5-24B-A2B** within the [`tuf`](file:///home/nii/workspace/tuf) inference runtime.

---

## 1. Model Overview & Hyperparameters

* **Model File**: `LiquidAI/LFM2.5-24B-A2B-GGUF/LFM2.5-24B-A2B-Q4_K_M.gguf`
* **File Size**: **13.53 GiB** (14,526,258,464 bytes on disk)
* **Architecture**: `lfm2moe` (Sparse Mixture-of-Experts with Hybrid Conv1D + GQA Trunk)
* **Total Layers**: **40 blocks**
* **Total Parameters**: **24.0 Billion**
* **Active Parameters**: **2.45 Billion per token** (2 leading dense blocks + top-4 routed experts)
* **Embedding Dimension ($d$)**: 2048
* **Context Length**: 131,072 tokens (128k)
* **Vocabulary Size**: 128,000 tokens
* **Attention Heads**: 32 Query Heads, 8 KV Heads ($d_{\text{head}} = 64$)
* **ShortConv Window ($K$)**: 3 (rolling state buffer = 2 past tokens per channel)
* **MoE Configuration**:
  * **64 Routed Experts** per MoE block
  * **Top-4 Routing** per token
  * **Expert FFN Intermediate Dimension**: 1,536
  * **Leading Dense Blocks**: 2 (Layers 0 and 1 are Dense FFN)
  * **MoE Blocks**: 38 layers (Layers 2..39)
* **Target Hardware Footprint**: **Hybrid VRAM + Host RAM** (Trunk + ~47% of experts in 8 GB VRAM; remaining experts mmap'd in 64 GB Host RAM).

## 2. Layer Composition Breakdown

The 40 blocks follow a strictly periodic structure:

| Layer Index | Trunk Operator | FFN Type | Expert Count |
| :--- | :--- | :--- | :---: |
| **Layer 0..1** | **ShortConv1D** ($K=3$) | Dense SwiGLU | Dense |

| **Layer 3..5** | **ShortConv1D** ($K=3$) | MoE (64 exp, top-4) | 4 active |
| **Layer 6** | **GQA Attention** (32 Q, 8 KV) | MoE (64 exp, top-4) | 4 active |
| **Layer 7..9** | **ShortConv1D** ($K=3$) | MoE (64 exp, top-4) | 4 active |
| **...** | ... | ... | ... |
| **Layer 38** | **GQA Attention** (32 Q, 8 KV) | MoE (64 exp, top-4) | 4 active |
| **Layer 39** | **ShortConv1D** ($K=3$) | MoE (64 exp, top-4) | 4 active |

* **Total Conv Layers**: **30 layers**
* **Total Attention Layers**: **10 layers**: `(L - 2) % 4 == 0` $\implies [2, 6, 10, 14, 18, 22, 26, 30, 34, 38]$
* **Total MoE Layers**: **38 layers** (`[2..39]`)
* **Leading Dense FFN Layers**: **2 layers** (`[0, 1]`)

## 3. VRAM & Cache Allocation Budget (RTX 3070 8 GB)

Usable VRAM: **~7,880 MiB**

| Component | VRAM Footprint | Description |
| :--- | :---: | :--- |
| **Trunk Weights (Resident)** | **623.4 MiB** | Embeddings, Conv in/out projections, Attention QKV, Output Head & Norms |
| **KV Cache & Buffers** | **~1,050 MiB** | Only 10 attention layers need KV cache; activation scratch & router buffers |
| **MoE LFRU Cache** | **~6,206 MiB** | Holds **~46.9% of all 2,432 expert slices** resident in GPU memory |
| **Host Mmap Fallback** | **~7,015 MiB** | Cold experts served from 64 GB DDR4-3200 system RAM |

### Projected Hit Rate & Performance
* Because 46.9% of all expert slices fit in VRAM (vs. only 24.4% in Qwen3.6-35B-A3B) and routing follows a power-law distribution, the **VRAM cache hit rate is projected at 88% – 92%**.
* Decode Speed Target:
  * Baseline (Phase 2): **68 – 75 tok/s**
  * Fused Kernels (Phase 3): **82 – 90 tok/s**
  * CUDA Graphs + Async Prefetch (Phase 4): **95 – 110 tok/s**
  * Speculative N-Gram Draft (Phase 5): **110 – 125 tok/s**
